# ADR-7: 删除是一等结局

- 状态：accepted
- 日期：2026-08-20
- 决策者：Flatline 设计（系统设计 v0.4 §2 原则 3、§4.3、§4.5）

## 背景

休眠资产持续消耗上下文并稀释触发。若产品只提供"修复"路径，用户无法低成本清理死资产；若清理是危险操作，用户会回避。清理必须与修复同等重要，且收益必须确定性可计算（描述占用的上下文、稀释效应），不能靠模糊的"质量分"（系统设计 v0.4 §2 原则 3；AGENTS.md §2 第 3 条）。

## 决策

删除/清理是一等结局：批量清理流提供确定性收益数字与可执行清单；任何清理/归档必须用户显式确认，生成可回滚记录——不物理删除文件，提供移除建议或 `.disabled` 方案。归档（`archived` 状态）声明"不再使用"，停止监护，可随时恢复。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 显式确认 + 可回滚清理（本决策） | 收益确定性可算；可回滚；符合写入纪律 | 用户需手动确认，非一键 | 采纳 |
| 自动清理（静默删除/禁用） | 零操作 | 违背写入纪律（AGENTS.md §3：绝不静默修改或删除资产） | 拒绝 |
| 只提示不执行（无清单） | 最保守 | 用户无法低成本完成清理，价值不兑现 | 拒绝 |

## 后果

- 正面：批量清理是新用户首日可兑现的价值（系统设计 §4.5）；收益数字全部确定性计算，满足证据纪律。
- 负面：清理路径必须实现显式确认接口与可回滚记录（DEVELOPMENT.md 审查清单）；`.disabled` 方案需在各 Harness 中验证兼容性。
- 对 MVP 边界：批量清理流属于 MVP（roadmap P6）；不引入任何自动写操作。

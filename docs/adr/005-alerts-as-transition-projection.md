# ADR-5: 告警是状态迁移的投影

- 状态：accepted
- 日期：2026-08-20
- 决策者：Flatline 设计（系统设计 v0.4 §3.4、§6）

## 背景

v0.3 中"任务"（decision_tasks）是独立对象，可被单独创建与删除，导致告警与状态机脱节、可被手工操纵。v0.4 以状态机为唯一裁决者（Vital State Machine），告警必须与状态严格一致（系统设计 v0.4 §3.3、§3.4）。

## 决策

告警是状态迁移（`state_transitions`）的投影：不可独立创建或删除；同一资产同一状态不重复告警。"忽略"处置持久化于 `dispositions`，作用域为当前状态实例；迁移到其他状态后再次进入原状态视为新实例，重新告警。schema 中不设 `decision_tasks` 表。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 告警为迁移投影（本决策） | 告警与状态永远一致；无独立告警存储需维护 | 告警不可手工编辑 | 采纳 |
| 独立告警/任务表（v0.3 方案） | 可手工管理告警 | 告警可脱离状态存在，产生"僵尸告警"，违背证据纪律 | 拒绝 |
| 每次评估都发通知 | 信息全 | 同状态重复告警，噪音淹没真实迁移 | 拒绝 |

## 后果

- 正面：`state_transitions` 表即告警数据源，下钻路径（告警 → 判定依据 → 原始事件）天然成立；"状态迁移才开口"原则（系统设计 §2 原则 2）在数据层强制。
- 负面：告警文案完全由判定依据生成，必须满足 ADR-8 的一句话可解释标准。
- 对 MVP 边界：无额外范围影响；`dispositions` 表属于 P1 schema。

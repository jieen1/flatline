# ADR-6: 验收降级为修改后验证

- 状态：accepted
- 日期：2026-08-20
- 决策者：Flatline 设计（系统设计 v0.4 §0、§4.4、附录 B）

## 背景

v0.3 的正式改善轮次（ImprovementCycle：目标指标 + 防回归 + 观察窗 + 统计验收）是统计问题，需要窗口与样本量；个人用户环境变化快于样本累积，多数结论将是 inconclusive（系统设计 v0.4 §0、附录 B）。修改资产后仍需一个默认验证机制。

## 决策

修改后的默认验证采用单事件规则：`awaiting_resurrection` 期间，首次观测到该资产重新参与且未违背 → 迁移至 healthy 并发修改后验证通过通知；修改后 N 个机会仍零参与 → 修改后验证未通过通知。无最小样本要求。统计验收整体移入附录 B Backlog，UI 与代码均不实现。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 修改后验证（单事件验证）（本决策） | 个人数据量足够；即时反馈；成本极低 | 单事件可能误判（一次偶然参与） | 采纳 |
| 正式改善轮次（统计验收） | 结论更稳健 | 样本需求超出个人用户数据现实，多数 inconclusive | 拒绝，整体移入 Backlog |
| 不做任何验证 | 最简单 | 修改后无反馈，产品失去"确认修复生效"的核心价值 | 拒绝 |

## 后果

- 正面：修改后验证通过是正向通知，与问题告警同权重送达（系统设计 §3.4）；schema 不含 `improvement_cycles` 系列表。
- 负面：单事件验证存在假阳性可能，UI 需如实标注观测等级；验证未通过通知需引导回诊断页。
- 对 MVP 边界：ImprovementCycle 明确不进入 MVP（AGENTS.md §6）；重启条件见系统设计附录 B（真实用户反馈修改后验证不足，且 Session 量级足以两周内积累可比样本）。

# ADR-10: 状态历史可廉价重放

- 状态：accepted
- 日期：2026-08-20
- 决策者：Flatline 设计（系统设计 v0.4 §7.2、§9）

## 背景

阈值与 detector 会随版本演进（如沉默判定 N 值调整、新 detector 上线）。若状态历史（`vital_states`、`state_transitions`）只能增量计算，升级后历史与新规则不一致，回测验收（roadmap 验收标准 1：在开发者 ≥3 个月真实历史上回放状态机）无法进行。

## 决策

派生层（tracker、detector、状态机）必须可整体重算：`vital_states` 与 `state_transitions` 携带 detector/schema 版本，阈值与 detector 升级后对全量状态历史做廉价回算。回测即验收：升级前先在真实历史上回放并人工核验判定。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- |
| 全量可重放（本决策） | 阈值/detector 升级安全；回测验收可行 | 派生层必须无副作用、可幂等重算 | 采纳 |
| 仅增量计算 | 实现简单 | 升级后历史与新规则不一致，无法回测，规则变更不可验证 | 拒绝 |
| 双轨（新旧规则并行存储） | 保留旧结果 | 存储与查询复杂度翻倍，个人数据量下无必要 | 拒绝 |

## 后果

- 正面：回测验收（roadmap P7）成为规则变更的强制门禁；首次导入后历史回测即刻点亮生命体征墙（验收标准 3）。
- 负面：派生层代码必须保持纯函数式（输入 canonical 事件 + 资产快照，输出状态），任何隐式状态或外部副作用都会破坏可重放性。
- 对 MVP 边界：重放能力属于 MVP（P1 schema 携带版本字段；P7 回测验收）。

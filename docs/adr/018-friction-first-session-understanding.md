# ADR-18: 从摩擦出发理解会话历史

- 状态：accepted
- 日期：2026-08-22
- 决策者：Flatline maintainers

## 背景

v0.4 把产品建立在"资产生命体征"上。把 874 个本地真实会话导入后，只有 136 个会话能对应到任何资产的相关任务，146/153 个资产长期处于 `no_opportunity`。检测器没有错，但在个人用户的真实数据上它大部分时间无话可说。同一批数据里，明确记录的工具失败、非零退出和用户中断却遍布每个项目。

## 决策

1. 会话历史本身成为一等对象：按项目（`cwd`）、harness、时间、规则标签、用户标签组织；提供服务端筛选、分面、搜索（SQLite FTS5 trigram）、置顶与笔记。用户标注只写本地数据库。
2. 摩擦成为主路径之一：`friction_records` 扩展为封闭类别（一句话规则，派生可重算），新增 `user_interrupt` 类型；页面以项目 × harness × 类别组织，每条记录回链到会话中的具体事件。
3. 总览页回答"这段时间我在哪些项目做了什么、摩擦集中在哪"，取代"墙即总览"。资产墙保留为一级页但不再是默认页。
4. 性能是功能：daemon 先监听后导入；原生文件指纹持久化；会话级统计投影；版本化响应缓存与 ETag；数据库连接池。

本决策修订 UI 指南 §1（三页）与 §11 第 9 条（"三页够了"）；证据纪律（ADR-8/13/14/17）、写入纪律、隐私边界不变。不引入 AI 分析：标签与类别全部是可审阅的规则。

## 后果

- 新增派生表 `session_stats`、`session_tags`、`native_files`、FTS 索引，以及用户数据表 `session_annotations`。
- 摩擦类别是规则产物，规则版本变化要整体重算；不是质量评分。
- 资产监护链路保持不变，仍按自身基线判定；只是入口位置后移。

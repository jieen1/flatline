# Flatline 价值复盘与规划 · 2026-08-29

> 方法：不是读文档得出的结论。本轮先把系统在本机全量跑通（973→977 会话、35.6 万事件），
> 然后**以真实用户身份使用它回答自己的问题**，记录它答得上与答不上的地方；
> 再对照外部同类工具的现状，收敛出核心价值与下一步。
> 所有数字都来自本机真实数据，每个都能在 API 里复查。

## 1. 这台机器的数据说了什么：用户画像变了

设计文档假设的用户是"一个人 + 一个 agent 聊天改代码"。本机数据说的是另一件事：

| 事实 | 读数 | 怎么查 |
| --- | --- | --- |
| 子代理会话占多数 | 977 个会话里 679 个是子代理（69%） | `/sessions/facets` |
| 舰队是常态而非偶发 | 每周 4–10 个"主会话带 ≥3 个子代理"的舰队，连续 6 周 | sessions 按 parent 聚合 |
| 单次舰队规模 | 最大 108 个子代理：24 支完整的 dev/qa/reviewer/gatekeeper 小队跑一次冲刺审计 | `parent=claude_code:6a251c15…` |
| 单次舰队代价 | 该会话父+子合计 **6.2B token**（本机总量的 18%）、50 小时 | 同上 |
| 角色即组织 | agent_role 里是 dev-1982 / qa-1340 / gatekeeper-1339——按 issue 编号组建的小队 | sessions.agent_role |

**用户不是"在用一个 agent"，而是在"运营一支 agent 舰队"。**
一次典型工作（微信模板功能，issue 1982）：主会话指挥 dev（125.7M token）→ 两个 MR 审查
→ 两轮 QA 复测 → 7 个便宜的探路 agent，父+子 592M token 交付一个功能。

这不是本机独有的怪癖。外部同期动向：LangSmith 2026 新增了 Fleet（agent 舰队管理 + 统一成本视图 +
自动找反复失败模式的 Insights Agent）；AgentOps 等一批工具都在做 agent 群的轨迹、成本、错误。
**但它们全部要求接入 SDK 或走它们的网关**。没有人做"读本机 harness 已经写下的转写、零接入、纯本地"
这个位置——那正是 Flatline 已经站着的地方。

## 2. 真实使用中发现的三个价值断层

### 断层一：舰队是真正的工作单元，但系统把它拆成孤立的行

我想回答"那次 6.2B token 的冲刺审计买到了什么"，实际经历是：
会话页看到"子代理 108"这个数字 → 详情页看不到孩子 → 只能自己拼
`/sessions?parent=…` 逐个把 108 行的 token/摩擦/角色加起来。

系统**有全部事实**（parent_session_id、agent_role、每个孩子的度量），缺的只是"按树聚合"这一层。
这是典型的 ADR-20 式机会：不需要新表、不需要新采集，读时投影即可。

### 断层二：token 总量作为头号指标，失真 50 倍

全库 token 分解（session_usage 全表求和）：

| 分量 | 量 | 占比 |
| --- | --- | --- |
| 缓存读取（cache read） | 47.0B | **98.0%** |
| 缓存写入（cache write） | 862M | 1.8% |
| 新输入（input） | 18M | 0.04% |
| 输出（output） | 91M | 0.19% |

按厂商定价，缓存读取约是新输入价格的 1/10、输出价格的 1/50。
一个"378.4M token"的会话，其中 373.6M 是缓存读——**页面上最大的那个数字，
与"这次花了多少钱/配额"几乎无关**。真实工作量（input+output+cache write）全库只有 970M（2%）。

系统已经逐项存了四个分量（ADR-22 甚至有逐消息 usage），只是页面把总和放在了 C 位。
这不违背证据纪律——四个数都是事实——但**选错了领衔的事实**。

### 断层三：监护仪没有"现在"

产品自我定位是"监护仪"（监护仪的第一屏是**实时生命体征**），但落地页是一个 30 天统计视图。
本机每周有 4–10 次舰队在跑、单次 50 小时；跑的过程中用户唯一的问题是
**"现在怎么样了、卡住没有、要不要干预"**——目前只有会话行上一个小小的"进行中"徽标。
`in_progress` 的判定已经存在，5 分钟增量摄取已经存在，缺的是把"正在发生"组织成第一屏。

### 旁证：资产层在真实数据上确实无话可说

883 个资产：0 个需要注意、872 个"没有相关任务记录"。ADR-18 把资产降为下钻层是对的，
本轮实测再次确认——**不要再往资产层投入**，它的机制留着，入口继续后置。

## 3. 核心价值的一句话

> **Flatline 是本机 agent 舰队的黑匣子 + 行车记录仪：零接入地回答
> "我的 agent 们做了什么、代价是什么、哪里反复卡住、这次改进有没有用"。**

四个问题对应四层，前三层已有地基，第四层（规则闭环）本轮第一次走通：
缺口 5→0，两条 watch 基线已冻结（Edit 160 次/58 会话、Write 33 次/21 会话，14 天窗口）。

## 4. 规划（按价值排序）

### P16-1 舰队汇总（本轮实现）

**谁做什么**：会话详情页对 `subagent_count > 0` 的会话增加"团队"区块；
新端点 `GET /api/v1/sessions/{id}/fleet` 做读时聚合（无新表、无迁移，ADR-20 纪律）。

| 内容 | 口径（一句话可解释） |
| --- | --- |
| 全树代价 | 父 + 全部子会话的四个 token 分量分别求和，"实际工作 token" = input+output+cache_write |
| 每个孩子一行 | 角色、标题、token（总/工作）、摩擦数、时长、进行中标记 |
| 结局证据 | 树内记录到的编辑行、改动文件数、`git commit/push/merge` 命令数（claude_code 98% 的命令无退出码——如实标"结果未记录"，不猜成功） |

**容易误读的地方**："树内有 commit 命令 = 这次任务成功了"——不是。系统只陈述
"记录到 N 次 commit 命令、其中 M 次未记录到失败"，成败判断留给读者（ADR-8）。

### P16-2 头号指标换位：工作 token 领衔（本轮实现于舰队区块，总览后续跟进）

页面凡是领衔展示 token 的地方，把"工作 token"（input+output+cache write）放前面，
总量与缓存读取并列在后。四个数都已在库，纯展示换位。

### P16-3 "现在"视图（下一轮）

落地页顶部增加"正在进行"区：`in_progress` 的主会话及其舰队，行内给
最近事件时间、最近一条摩擦、当前活跃的子代理数。判定全部来自已有事实
（最近事件 < N 分钟 = 进行中，N 写进说明句）。不做推送、不做干预——先把"看见现在"做出来。

### P16-4 会话标题剥离 harness 包装（本轮实现）

65 个会话（6.7%）的标题是一整段 `<teammate-message …>` 原文。舰队区块一做，
这些孩子行的可读性问题会放大。规则：`title` 命中注入前缀表时，display_title 依次取
标签的 `summary` 属性 → 包装内第一行非空文本；`title_source` 如实改标 `synthesized`
（这名字是系统构造的，不再冒充源头 AI 起的名）。原 title 原样保留在库，随时可查。

### 不做 / 缓做

- **美元成本换算**：定价是外部易变事实且随折扣/订阅不同而不同，写死进代码违背"每个读数可解释"。
  工作 token 已经承担了"代价有多大"的 90% 信息量。若做，做成用户自填的本地价格表。
- **AI 分析层**：维持 MVP 边界。舰队汇总证明了"读时投影就能把价值翻一倍"，先把确定性的做完。
- **资产层新功能**：见 §2 旁证。

## 5. 外部参照（调研于 2026-08-29）

- LangSmith：2026 年新增 Fleet（舰队部署管理、统一成本视图、Insights Agent 自动找反复失败模式）——
  验证了"舰队 + 成本 + 反复失败"正是这个品类的价值三角；但要求走它的平台。
- AgentOps 等：LLM 调用/工具/多 agent 轨迹、token、成本、错误全采——同样要求 SDK 接入。
- ccusage（18.2k stars）：读同一批本地数据但只做费用报表——证明"本地转写"这个数据源有大众需求，
  也证明只做费用不够。
- Flatline 的独占位：**零接入（harness 已经写了转写）+ 跨 harness + 纯本地 + 事实纪律**。

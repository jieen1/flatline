# Flatline「摩擦」页面设计方案 v1

## 1. 目标与边界

新增一个一级页面，用于回答两个问题：

1. 哪个项目在什么 harness 下出现了哪些明确记录的摩擦？
2. 某一类摩擦累计出现多少次，每一次发生在什么会话、什么时间、什么工具或事件上？

这个页面的主维度是「项目 × harness」，不是资产维度。资产只作为事件证据的一部分出现，不能成为页面的分组主键。

页面只展示已有明确证据的事件，不做推测性健康评分，不把缺失数据显示成零，也不写因果结论。

## 2. 信息架构

### 2.1 一级入口

在现有左侧导航中新增：

- 文案：`摩擦`
- 图标：复用原型已有的 `triangle-alert`
- 位置：`会话`之后、`变化时间线`之前
- 路由：沿用当前 hash 路由风格，建议为 `#/friction`

不新增侧边栏筛选区。筛选放在页面内容区顶部，保持与当前会话列表一致，避免把项目筛选、harness 筛选藏到左侧导航中。

### 2.2 页面层级

页面分为两层：

1. **摩擦总览**：按项目 × harness 聚合，展示分类统计。
2. **项目+harness 详情**：展示该组合下每一次摩擦事件，并提供证据检查器和会话跳转。

点击总览中的一行进入详情，不使用临时弹窗承载大量记录。

## 3. 总览页布局

```text
┌ 左侧现有导航 ┐ ┌──────────────────────────────────────────────────────┐
│ 资产          │ │ 摩擦                                  [重新扫描]     │
│ 会话          │ │ 按项目与 harness 查看明确记录的摩擦事件              │
│ 摩擦 active   │ │                                                      │
│ 变化时间线    │ │ [全部项目] [全部 harness] [全部类型] [时间范围]       │
│ 统计          │ │ [搜索项目、工具或会话]                    [排序]       │
│               │ │                                                      │
│               │ │ [明确摩擦事件] [工具调用出错] [非零退出] [涉及会话]   │
│               │ │                                                      │
│               │ │ 项目 × harness                                      │
│               │ │ ┌项目┬harness┬总数┬工具错误┬非零退出┬会话┬最近发生┐ │
│               │ │ │项目A│Claude │ 12 │   8    │   4    │  6 │ ...    │ │
│               │ │ │项目A│Codex  │  2 │   2    │ 未记录 │  1 │ ...    │ │
│               │ │ └───────────────────────────────────────────────────┘ │
└───────────────┘ └──────────────────────────────────────────────────────┘
```

### 3.1 页面头部

- 标题：`摩擦`
- 说明：`按项目与 harness 查看明确记录的摩擦事件`
- 右侧操作：复用现有的 `重新扫描` 按钮样式和扫描状态反馈
- 不显示无法解释的总分、健康分、排名或“风险等级”

### 3.2 筛选工具栏

所有筛选使用现有页面的工具栏、分段控件、选择器和搜索输入组件，不创建一套新的筛选视觉。

筛选项：

- 项目：`全部项目`，项目名称旁显示工作目录；另有明确的 `项目未记录`
- harness：`全部`、`Claude Code`、`Codex`，使用当前已有的品牌图标
- 类型：`全部`、`工具调用出错`、`非零退出码`、`资产绕行`
- 时间：`全部时间`、近 7 天、近 30 天、近 90 天、自定义范围
- 搜索：支持项目展示名、工作目录、工具展示名、会话名称、任务文本
- 排序：`摩擦最多`、`最近发生`、`涉及会话最多`

搜索框应直接在原有输入框内输入，不在下方重复弹出第二个输入框。

筛选变化后，统计卡片、表格行和分页状态一起更新；筛选条件保留在 URL 状态中，刷新页面后不丢失。

### 3.3 统计卡片

复用当前统计页的卡片容器、数字层级、边框、圆角、间距和 hover 状态。每张卡片使用原型中已经存在的图标，并且图标、文字、颜色同时表达含义。

建议四张卡片：

| 卡片 | 含义 | 交互 |
| --- | --- | --- |
| 明确摩擦事件 | 按事件来源去重后的明确事件总数 | 点击清除类型筛选，保留项目和 harness 筛选 |
| 工具调用出错 | `is_error=true` 的记录数 | 点击筛选“工具调用出错” |
| 非零退出码 | 明确记录 `exit_code != 0` 的记录数 | 点击筛选“非零退出码” |
| 涉及会话 | 至少包含一条摩擦记录的会话数 | 点击按会话数量排序 |

卡片下方只放口径说明，例如“已完成扫描范围内”；不显示未经定义的摩擦率。

当扫描不完整或数据源没有记录时显示 `未记录` 或数据完整性提示，不能把未知值显示成 `0`。

### 3.4 项目 × harness 表格

表格是总览页的主要内容，行主键为一个明确的项目+harness 组合。

列顺序：

1. 项目：展示名，下面显示工作目录或可读路径
2. harness：Claude Code / Codex 品牌图标与文字
3. 明确摩擦事件：按来源事件去重后的总数
4. 工具调用出错：明确 `is_error=true` 的数量
5. 非零退出码：明确 `exit_code != 0` 的数量
6. 资产绕行：`asset_violation` 事件数量
7. 涉及会话：去重后的会话数
8. 最近发生：最近一条记录时间
9. 操作：复用 `chevron-right`，文字为 `查看详情`

表格规则：

- 使用现有列表行、分隔线、徽标和来源图标，不新画一套表格皮肤。
- 摩擦类型使用现有语义色：错误使用红色、非零退出使用橙色、未知/未记录使用灰色；颜色旁必须有文字。
- 行可点击，点击整行进入详情；操作列只作为清晰的可点击提示，不制造重复弹窗。
- 数据量大时按批次懒加载；首次只渲染首批，滚动接近底部再取下一批。
- 总览接口优先完成聚合、筛选和排序，浏览器不加载全部原始事件后再计算。

## 4. 项目+harness 详情页

### 4.1 头部

详情页沿用现有会话详情的页面骨架和返回行为：

- 返回：`摩擦`
- 项目标题：项目展示名
- 辅助信息：工作目录、harness 品牌图标、harness 名称
- 时间范围：当前筛选范围
- 不用原始项目 ID 作为主标题

如果没有会话名称，显示 `会话名称未记录`，再将会话 ID 作为次要定位信息；不能只把不可读的 `toolu_...` 或随机 ID 当成标题。

### 4.2 详情统计条

复用现有的标签、状态徽标和卡片样式：

- 全部明确摩擦：N
- 工具调用出错：N
- 非零退出码：N
- 资产绕行：N
- 涉及会话：N
- 首次记录：时间
- 最近记录：时间

类型统计可互相重叠：同一事件同时具备 `is_error=true` 和非零退出码时，它可以同时出现在两个分类中；“全部明确摩擦”始终按来源事件去重。界面要在统计条下明确写出这条口径，避免用户把分类相加后误认为总数。

### 4.3 事件列表

列表复用当前会话详情中已经存在的列表行、事件徽标、分隔线和选中态。

每行至少展示：

- 发生时间
- 摩擦类型
- 工具的可读名称；原始工具 ID 只作为次要证据
- 会话名称；未记录时显示清晰的未记录文案
- 任务文本摘要（若有）
- 明确证据摘要，例如 `is_error=true`、`exit_code=1`
- 事件来源定位信息

工具调用出错的示例文案应是：

`工具调用出错 · Read · exit_code=1 · 2026-08-22 14:32`

而不是直接把一串工具调用 ID 当作事件标题。

列表支持：

- 类型筛选
- 最近发生/最早发生排序
- 懒加载或服务端分页
- 点击一行更新右侧证据检查器
- 当前行高亮，并保持滚动位置

### 4.4 右侧证据检查器

采用当前会话详情已经使用的“列表 + Inspector”模式，不新增陌生的下方弹层。

检查器分为三组：

1. **事件摘要**：时间、类型、工具展示名、会话名称、harness、项目
2. **明确字段**：`is_error`、`exit_code`、事件类型、观测等级、来源事件 ID
3. **证据与定位**：原始 payload、locator、会话跳转、上下文位置

原始 payload 保持原样，只做折叠、截断和复制，不改变证据内容。检查器中使用现有的 Evidence Block、Provenance Badge、Session Reference 等组件。

会话跳转应进入已有会话详情，并定位到对应事件或摩擦轴记录；如果无法定位到具体事件，要明确显示“仅能定位到会话”，不能假装已定位。

## 5. 摩擦分类与数据口径

### 5.1 初始分类

只实现当前系统已有证据能够支撑的分类：

- **工具调用出错**：事件明确记录 `is_error=true`
- **非零退出码**：事件明确记录 `exit_code` 且值不为 0
- **资产绕行**：事件类型为 `asset_violation`

不使用“失败率”“严重程度”“影响程度”等没有分母或判定规则的词。

### 5.2 总数去重

同一来源事件可能同时满足多个分类条件：

- 分类计数可以重叠
- 总摩擦事件数按来源事件去重
- 涉及会话数按 session 唯一标识去重

事件来源优先使用 `source_event_id`；资产绕行等没有该字段时使用事件自身唯一 ID。接口必须返回数据是否完整，前端不能自行猜测是否还有未加载记录。

### 5.3 项目识别

现有会话主要提供 `cwd`，因此第一版按规范化工作目录形成项目展示身份：

- 规范化路径作为稳定项目键
- 目录名只有在当前结果中唯一时才作为短名称
- 同名项目存在歧义时展示完整路径或可读路径尾部
- 没有 `cwd` 时归入 `项目未记录`
- 不因为资产存在、事件数量或目录名相同就推断项目关系

后续如果引入显式项目映射，应优先使用显式映射，但不能改变已有记录的原始来源。

### 5.4 harness 识别

harness 直接使用会话来源字段，并复用现有的 Claude Code / Codex 图标和品牌色。未知来源显示 `harness 未记录`，不强行归类到某一个 harness。

## 6. 读取接口设计

页面需要一个只读的摩擦聚合接口，以及一个项目+harness 明细接口或等价的查询能力。

### 6.1 总览查询能力

查询需要支持：项目、harness、类型、时间范围、关键词、排序、分页/批次大小。

返回内容至少包括：

- 汇总计数及其口径
- 项目+harness 行
- 每行的分类计数、会话数、首末时间
- 数据是否完整
- 当前批次、总数、是否还有下一批

### 6.2 明细查询能力

明细查询按项目+harness 组合返回：

- 分类汇总
- 去重后的总事件数
- 每条摩擦记录的时间、类型、会话、工具、证据字段、观测等级、来源定位和 payload
- 是否截断、是否完整

查询层负责聚合、去重、筛选和排序；前端只负责展示，避免大数据量下浏览器卡顿或口径漂移。

## 7. 状态、国际化和主题

### 7.1 加载与空状态

- 首次加载：复用当前页面 skeleton 和 loading 状态
- 查询中：保留筛选条件，表格显示局部加载，不闪回整页空白
- 完整扫描后确实没有记录：`没有检测到明确摩擦记录`，同时展示检测口径
- 数据源未完成采集：`摩擦数据尚未完整记录`，不能显示为“0 次”
- 项目缺少工作目录：单独显示 `项目未记录`
- 查询错误：复用现有错误卡片，提供重试，不伪造空结果

### 7.2 中英 i18n

所有页面自有文案、筛选项、表头、空状态、错误状态、检查器字段和无障碍标签都必须进入现有中英文案表。原始 payload、工具返回内容和用户输入保持原语言，不做机器翻译或改写。

### 7.3 深色模式

只使用现有主题变量、背景层级、边框、文字、状态色和阴影，不单独写一套深色页面。所有新增卡片、表格、检查器和弹性滚动区域必须在浅色和深色主题下分别验证。

## 8. 必须复用的现有组件与图标

| 页面元素 | 复用对象 |
| --- | --- |
| 左侧导航 | 当前 sidebar、active 状态、项目范围样式 |
| harness 标识 | 现有 Claude Code / Codex source icon |
| 摩擦入口和类型 | 原型已有 `triangle-alert`、`circle-slash`、`unlink` 等图标 |
| 统计卡片 | 统计页现有卡片结构和数字层级 |
| 筛选 | 会话页现有分段筛选、搜索框、排序选择器 |
| 事件行 | 会话详情现有事件列表和选中态 |
| 详情检查器 | 现有 Inspector、Evidence Block、Session Reference、Provenance Badge |
| 返回/展开 | 现有 `chevron-right`、返回和折叠交互 |
| 加载/空状态 | 当前 skeleton、empty state、error state |

禁止为这个页面随意引入新的图标库、拟物图标、emoji、纯色圆形占位图或与原型不一致的状态符号。

## 9. 实施顺序

### 第一步：先锁定数据口径

补齐工具错误、非零退出码、资产绕行三类的可区分投影，并明确同一事件多分类时的去重规则。用带明确字段的测试 fixture 验证 12 次工具错误能够稳定返回 12 条。

完成标准：数据库查询结果、接口结果和现有会话详情中的摩擦记录口径一致。

### 第二步：实现只读聚合查询

加入项目+harness 聚合、过滤、排序、分页和明细查询。所有查询都返回完整性和截断信息。

完成标准：可以仅通过接口得到项目 A + Claude Code 的分类计数和每条事件详情，不依赖前端二次猜测。

### 第三步：接入总览页

严格复用当前导航、卡片、筛选、表格、图标、颜色和滚动组件，加入懒加载。

完成标准：切换项目、harness、类型、排序和搜索后，卡片与表格同步更新；数据量大时页面仍可滚动并按批次加载。

### 第四步：接入详情页和证据检查器

复用会话详情的列表 + Inspector 模式，点击总览行查看全部记录，点击事件查看证据，点击会话跳转已有详情。

完成标准：用户可以从“工具调用出错 12 次”逐条查看 12 次发生时间、会话、工具和证据，并能回到来源会话。

### 第五步：完成主题、i18n 和视觉验收

逐页面验证浅色、深色、中英文、加载、空数据、未记录数据、错误和超长列表；使用原型图标清单逐项对照并保存截图结果。

完成标准：没有新增自定义视觉语言，没有灰色无意义占位区域，没有第二个搜索输入框，没有无法解释的数字或文案。

## 11. 当前已知缺口

当前已有摩擦记录和会话级摩擦展示，但还没有完整的项目+harness 聚合页面；现有摩擦投影也需要在分类维度和多分类去重方面补齐。因此这次设计明确把“数据口径和聚合接口”放在 UI 之前，避免先做出看似完整但统计不可信的页面。

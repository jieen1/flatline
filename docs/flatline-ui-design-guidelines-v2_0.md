# Flatline UI 设计思路与原型指南

> 面向 UI/UX 设计与原型开发的独立说明 · v2.0 · 2026-08-19
> 相对 v1.0 的根本变化：核心 UI 从"工作台 + 改善工作区"换为"生命体征墙 + 诊断页"。核心故事从 12 步改善闭环换为 6 步监护循环。历史版本的规则已在本文件需要处重述。
> 引用文档说明：v1.0 UI 指南未包含在本仓库；正文所引历史章节属于设计输入，实现以本文件已展开的规格为准，不因历史引用缺失而猜测。

## 0. 先理解产品：一句话与一个比喻

> Flatline 是你的 Agent 资产监护仪：它知道每个 Skill、每份 AGENTS.md 是活着、垂死、已死还是从未活过，并在状态变化的那一刻告诉你。

比喻定调设计气质：**监护仪，不是驾驶舱**。监护仪安静、可信、平时不打扰、响的时候一定有事、每个读数都能解释。产品不是 Session 大盘（AgentView 已存在）、不是任务管理器（v1.0 的工作台已废除主位）、不是评分系统。

### 0.1 产品的核心故事（黄金路径，6 步）

1. 用户安装，首次扫描历史 → **生命体征墙即刻点亮**：24 个资产——15 健康、2 沉默、1 失效、5 休眠、1 不可观测；
2. 墙上 `sql-migrations` 标着沉默："此前同类任务 10 次中 7 次被调用；最近 8 次 0 次。起点前 2 天：Claude Code 升级 2.14"；
3. 用户点开诊断页：参与曲线在升级标记点后归零；体检发现它引用的迁移脚本路径已改名；
4. 用户点"修改"，在 Diff 中更新路径，保存 → 资产进入"修改后验证"；
5. 当天下午的一个真实 Session 里它被重新调用 → 修改后验证通知："修改后首次被调用，未发现违背"；
6. 三个月后墙上一直安静——直到某次模型切换后它再度沉默，系统再次开口。

**第二路径（清理，同样必须演示）**：墙的休眠区显示"5 个资产 90 天零参与，描述合计约占每次 Session 1.2k token" → 批量清理页 → 用户归档 4 个保留 1 个 → 收益立即显示。

原型验收标准：一条连续点击路径讲完 6 步 + 清理路径。讲不通 = 信息架构没成立。

### 0.2 核心对象（五个，替换 v1.0 §1.2）

| 对象 | 用户心智 | 主要出现位置 |
| --- | --- | --- |
| 资产 Asset | 我长期维护的工作方法 | 生命体征墙、诊断页 |
| 生命体征 VitalState | 这个资产现在活着吗 | 墙上每行的状态徽章与曲线 |
| 状态迁移 StateTransition | 刚刚发生了什么变化（= 告警 = 通知） | 通知、时间线、诊断页起点 |
| 会话 Session | 一次真实工作的原始证据 | 会话页、证据下钻 |
| 处置 Disposition | 我对一次告警做了什么 | 诊断页动作区、资产历史 |

最必须坚持的一条：**墙上一行是一个资产的当前状态，不是一条任务。**没有"待办数"，只有状态分布。

## 1. 一级信息架构（三页）

```text
生命体征（首页） / 会话 / 变化时间线
```

| 页面 | 回答 | 不承担 |
| --- | --- | --- |
| 生命体征 | 我的资产哪些活着、哪些死了、哪些在耗上下文 | 不做任务队列、不做 Session 浏览 |
| 会话 | Agent 具体做了什么（沿用 v1.0 §13 全部设计，含 EffectiveBundle 检查器） | 不管理流程 |
| 变化时间线 | 环境变化、资产变化、状态迁移在同一时间轴上如何对齐 | 不判因果 |

诊断页是墙的下钻（路由 `/assets/<id>`），不是一级入口。v1.0 的总览与工作台取消：**墙即总览，通知即任务**。

---

## 2. 生命体征墙（首页，产品身份所在）

### 2.1 结构

按严重度分区的资产列表，从上到下：

1. **需要注意**：失效 / 沉默 / 被绕行 / 修改后验证未通过（有告警的状态）；
2. **观察中**：衰退 / 修改后验证；
3. **健康**；
4. **休眠**（折叠区，带清理入口和合计上下文占用）；
5. **没有相关任务记录 / 不可观测 / 已归档**（折叠区，灰度呈现，如实解释）。

页面顶部一句话状态摘要（沿用 v1.0 §4.2 页头规范）："24 个资产：2 个需要注意，5 个休眠可清理，其余正常。"没问题时就说没问题——空的"需要注意"区显示"过去 14 天没有状态变化"，不制造焦虑。

### 2.2 核心组件：Asset Vital Row（全产品最重要的一个组件）

一行从左到右：

| 元素 | 规格 |
| --- | --- |
| 状态徽章 | 颜色 + 图标 + 文字三者共同表达（沿用 v1.0 §14.2 颜色语义；灰=未知/休眠，红=失效/被绕行，橙=沉默/衰退，绿=健康/修改后验证通过） |
| 名称与类型 | `skills/sql-migrations` · Skill · 作用域 |
| **参与度 sparkline** | 近 8–12 周参与率微型曲线；上面叠加**变化标记点**：资产自身版本变更（实心点）、Harness/模型等环境变化（空心点）。这是信息密度最高的元素，必须一眼能看出"曲线在哪个标记点后掉下去" |
| 基线对比 | "7/10 → 0/8" 分子分母原文，永不只给百分比 |
| 最后参与 | "最后调用：8 月 2 日" |
| 观测等级角标 | 按系统设计 §3.1 的 canonical 枚举逐值展示：invoked=直接观测 / observed-use=规则推导 / loaded=已加载 / offered=已提供 / inferred=推断关联 / unknown=未记录；参与形式与观测等级分开表达 |

高频更新的资产与低频资产同住此行：区别只是实心标记点更密，曲线随版本起伏自然可见。不为高频资产做任何特殊 UI。

### 2.3 排序与筛选

区内默认按迁移时间倒序；支持按类型/作用域/状态筛选。**不提供"健康分排行"**——沿用 v1.0 §19.7 对不透明总分的禁令。

## 3. 资产诊断页

### 3.1 布局

| 区域 | 内容 |
| --- | --- |
| 页头 | 名称、类型、作用域、当前状态、状态起点（"沉默开始于 8 月 5 日"）、当前版本 |
| 主体第一屏 | **判定依据卡**：分子/分母/基线/机会定义原文 + 大号参与曲线（含全部变化标记）+ 起点 ±3 天对齐变化列表 |
| 主体第二屏 | **候选原因**，每条附证据、按证据强度排序：环境变化对齐 / 描述拥挤（新增了 N 个相似描述资产，相似度可点开）/ 引用体检失败项 / 自身某次修改对齐 / 该类任务本身消失了 / 无证据（如实标注"未知"） |
| 主体第三屏 | 参与漏斗现在 vs 基线（offered→loaded→invoked→followed，各环节标注观测等级，取不到的环节显示"该 Harness 未记录"而非 0） |
| 右侧动作栏 | 四个处置动作 + 处置历史 |
| 标签页 | 原文 / 版本 / 关联 Session / 处置历史（沿用 v1.0 §12 资产详情骨架） |

### 3.2 处置动作（单一主操作原则，沿用 v1.0 §7.4）

主按钮随状态语境变化：失效 → "修复引用"；沉默且体检通过 → "修改资产"。次要：清理、归档、忽略（接受现状，状态再迁移前不再打扰）。修改流复用 Diff Viewer；保存后页头即时切换为"修改后验证"，并说明验证条件（"下次同类任务中被调用且未违背即确认"）。

### 3.3 文案规则（沿用 v1.0 §16 并强化）

- 只写对齐，不写因果："沉默始于 CC 2.14 升级后 2 天内"，永不写"2.14 导致"；
- 每个比例带分子分母；
- unknown 用明确文案（"该 Harness 未记录候选集合"），不显示 0、空白或绿色；
- 候选原因区的每条都以"证据："开头，无证据的写"未知原因（无支持证据）"。

## 4. 批量清理流

从墙的休眠区进入，一个专注页面：

- 表格：休眠资产 × 最后参与时间 × 累计参与 × 描述 token 占用 × 建议（归档/保留）；
- 顶部合计："这 5 个资产的描述合计约占每次 Session 1.2k token"；
- 批量勾选 → 确认页展示将执行的具体操作（生成 .disabled 方案或移除清单，绝不静默改文件）→ 执行后显示收益并支持一键回滚；
- 情绪基调：整理房间的轻快，不是审判。休眠不是错误，只是"可能不再需要"。

---

## 5. 修改后验证结果（产品最重要的正向反馈）

- 通知文案："`sql-migrations` 修改后首次被调用（今天 14:32），未发现违背。" 点开直达那个 Session 的调用位置；
- 诊断页状态徽章切换为绿色 healthy，参与曲线上打一个验证标记点；
- 克制的庆祝：一次绿色状态迁移动画即可，无彩带、无分数、无"战报"。监护仪的喜悦是低声的；
- 验证未通过同样明确送达："修改后 8 次相关任务仍未被调用"，回到诊断页，候选原因列表刷新。

---

## 6. 变化时间线页

一条纵向时间轴，三类事件同轴呈现、颜色/形状区分：

- 环境变化（Harness 版本、模型、profile）；
- 资产版本变化（含谁改的：用户 / 检测到的外部变化）；
- 状态迁移（含修改后验证结果）。

支持按资产过滤（则成为该资产的传记）。这一页回答"最近这波沉默是不是同一次升级引起的"——多个资产的沉默迁移聚在同一个环境变化点附近时，做视觉聚簇提示（"3 个资产在 CC 2.14 后 5 天内先后沉默"——陈述句）。

---

## 7. 通知哲学

- **只有状态迁移产生通知**；同状态零重复；
- 分级：失效/沉默/被绕行/修改后验证未通过 = 需要注意；修改后验证通过 = 正向送达；衰退 = 仅墙上标注，不推送；休眠累积 = 每月一次汇总（"本月新增 3 个休眠资产"）；
- 每条通知自带判定依据原文，通知即证据摘要；
- 用户对某资产点"忽略"后，该资产当前状态实例的通知静默直到下一次状态迁移（忽略持久化为 Disposition，不跨状态实例，见系统设计 §4.3）；
- 无任何"回来看看"式召回通知。产品没话说的时候就不说话。

---

## 8. 证据、认识论与颜色

颜色必须与文字/形状共同表达；图表必带时间窗/分子分母/样本量/缺失/基线；不显示不透明总分。观测等级角标使用系统设计 §3.1 的 canonical 枚举。补充一条：**sparkline 是唯一允许省略轴标注的图表**，但 hover/点开必须展开为带完整分母的大图。

## 10. 首次使用（本设计的天然优势）

历史回测让墙**第一分钟就有内容**——不存在冷启动空页，也不存在 v1.0 时代担心的首日任务洪峰（状态是分布，不是队列）。首次流程：

1. 说明将读取的目录与本地承诺（沿用 v1.0 §17.1）；
2. 扫描进度实时点亮墙（资产逐个从灰变成状态色，这本身是最好的首次动画）；
3. 完成页一句话："发现 24 个资产：2 个可能已静默失效，1 个引用已失效，5 个休眠——从红色开始看。"
4. 历史区间的判定标注"基于安装前历史回测（inferred 关联）"，观测等级随使用时长升级的事实向用户明示（沿用系统设计 §3 快照器跃迁规则）。

## 11. 必须避免的设计误区（替换 v1.0 §19）

1. 把墙做成任务收件箱——墙是状态分布，没有"完成"概念；
2. 给资产打健康总分或做资产排行榜；
3. 用红色渲染休眠——休眠是中性灰，清理是整理不是审判；
4. sparkline 无标记点——没有变化标记的曲线只是装饰；
5. 通知里只说结论不带分母；
6. 把"没有相关任务记录"和"沉默"混为一谈——没有相关任务记录 ≠ 资产失效；
7. 把 inferred 的历史回测判定画得和安装后 derived 判定一样确凿；
8. 修改后验证做成大庆祝弹窗——监护仪不放烟花；
9. 为"看起来全面"恢复总览/工作台页——三页够了；
10. 弱化 Session 浏览——它仍是全部证据的下钻终点（沿用 v1.0 §19.10）；
11. 在诊断页写因果句式；
12. 一开始就设计团队/云端/账户（沿用 v1.0 §19.12）。

## 12. 原型交付与验收清单

交付顺序沿用 v1.0 §21 三阶段（结构 → 组件与状态 → 高保真贯通）。高保真必须用同一组真实感数据讲通 §0.1 的 6 步黄金路径 + 清理路径。

评审逐项确认：

- [ ] 只看首页，用户能说出"哪些资产死了、哪些在耗上下文"；
- [ ] 墙上没有任何"待办数"或"完成"概念；
- [ ] 每个沉默判定能看到分子、分母、基线和机会定义原文；
- [ ] 每条 sparkline 都有变化标记，且至少一个演示资产的曲线在标记点后明显变化；
- [ ] 诊断页候选原因全部证据前置，存在一条"未知原因"的诚实示例；
- [ ] 清理流展示确定性收益并可回滚；
- [ ] 修改后验证通知能一键直达那个 Session 的调用位置；
- [ ] "没有相关任务记录"与"不可观测"有独立的灰度表达；
- [ ] 历史回测判定与安装后判定的观测等级有视觉区分；
- [ ] 时间线页能演示"多个资产沉默聚簇在同一环境变化附近"；
- [ ] 全站无因果句式、无不透明分数、无空白式 unknown；
- [ ] 6 步黄金路径 + 清理路径均可连续点击走通。

## 13. 最终判断标准

设计完成后，用户应能自然说出：

> 它一直在帮我盯着我的 Skills 和配置——哪个悄悄死了它会告诉我为什么，我修完它会告诉我活没活过来，没用的它帮我清掉。

如果用户只记住"能看资产列表和曲线"，说明监护仪没有立起来；如果用户开始信任"它不响就是没事"，产品就成立了。

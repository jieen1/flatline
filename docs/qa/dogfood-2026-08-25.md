## 改动

- ● **新增 `/api/v1/insights`（代价与机会洞察层）**：六类封闭洞察——中断上下文、零改动高投入会话、
  卡死循环、重复读取、规则覆盖缺口、环境缺命令。每条自带判定规则原文（中英）、结构化 facts、下钻链接。

  此前 coverage 机器只有一条关键词规则，形同虚设；字典扩容后开始产出。
- ● **时间线批量折叠**：首扫/重扫/启动评估产生的同刻批量记录折叠成一行事实
  （"N 条 X 在同一时刻记录"），注意状态迁移（silent/broken/bypassed/degraded/awaiting_resurrection）
  逐条保留；kind 筛选仍逐条可查。
- ● **资产墙分区默认值对调**："几乎未使用"（清理候选所在）默认展开，911 个"没有相关任务记录"默认折叠。

## 已核实、未改的（防止后人误判为 bug）

- `grep/pkill exit 1` 落在 nonzero_exit 而非 expected_exit：**设计如此**。退出码语义表要求
  复合命令里所有候选程序都对该退出码有条目才套表（`exitcodes.go` 的 LookupExit 注释），
  `echo X && grep … | wc -l` 这类复合命令因 wc/sleep/echo 无条目而保守地保持"未解释的非零退出"。
- 事件层只存会话级 usage 聚合，逐消息 token 不在库里——**中断那轮烧掉多少 token 不可计算**，
  洞察层只陈述中断前的活动事实，不估算损失（ADR-20 后果节）。
- 改动行只统计编辑类工具（Edit/Write/apply_patch），bash 改写（sed -i 等）不计入——
  "零改动"卡片的判定规则原文里写明了这一点。

## 下一步（按价值排序，未做）

1. **中断轮次的 token 代价**：需要事件层存逐消息 usage（迁移 + 重读），才能把"被打断的投入"算成数。
2. **coverage_gaps 按项目分**（已知契约毛边 §27.8 第 2 条）：一个项目的规则替另一个项目挡缺口。
3. **洞察的窗口对比**：`compare=1` 给出上一窗口同口径读数，看"修了之后降没降"——修改后验证的会话版。
4. 工具习惯对比（sed/nl/cat vs Read）在 dogfood-2026-08-22 已观察，价值待定，未实现。

## 追加 · 规则闭环（同日晚，ADR-21）

按"规则层 CI"定位补上改进闭环的两拍，全部在真实库上走通：

1. **简报**：`/friction?group=signature` 的 100 个分组全部携带 brief；99/100 有样例
   （payload 无输出行的中断类回退到所在会话标题并如实标注）。真实样例——
   `apply_patch verification failed`（53 次/2 会话）：机制=补丁上下文对不上、落点=rule（附理由）、
   提示词含签名/规模/集中项目/样例，一键复制即可交给自己的 agent 起草。
2. **验证**：对该签名创建 watch（显式确认，窗口 14 天，基线冻结 53 次/2 会话）；
   摩擦页行内出现"验证中"徽标，面板显示"创建后发生 0 次，同项目会话 58 个"。
   状态机测试覆盖：verified→再发生→no_change 的回翻（闭环永不永久关闭）。
3. **确认门禁**：无 `confirmed:true` 的创建/取消一律 400，文案写明依据（AGENTS.md §3）。

**修正记录**：初版验证把创建前的旧事件计入"窗口内发生次数"，与判定规则句不符；
已改为严格按"创建后"计数（`post_count`），窗口计数降级为参考字段。

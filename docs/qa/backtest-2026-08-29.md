## 4. 回放发现的一个真实问题：首启引导期的"假 dormant"

时间线（同一天，可复现）：

| 时刻 | 事件 |
| --- | --- |
| 00:10:38 | 资产扫描完成，历史尚未读入；12 个 skill 判 `(new) → dormant` |
| 00:10–01:05 | **窗口期**：墙上显示"几乎未使用 12"，且该分区默认展开（2026-08-25 轮改的默认值） |
| 01:05:34 | 历史与参与证据落地，11 个转 healthy、1 个转 no_opportunity |

机制：`choosePrimary` 对 `PreviousState == ""` 的资产返回 dormant（注释明言"中性起点"）。
在空库首启场景，这个中性起点会**以"几乎未使用"的语义在墙上可见约一个导入周期**，
而它真正的意思是"还没看历史"。当天上午的 dogfood 记录（§8）把 `dormant: 12` 当作实测状态
写入——作者本人就被这个语义误导了一次，这就是问题真实性的最好证据。

**判定**：不算判定错误（状态机行为与注释一致），算**首启窗口的语义误导**。

**已定案（同日，ADR-26）**：深查后根因比上面猜的时序问题更干净——`choosePrimary` 对首次
评估**无条件**返回 dormant，且排在参与证据检查之前；参与记录早已在库里，判定却不看它。
修法不需要 `pending_history` 新枚举：首次评估有参与证据 → 直接 healthy；无证据才取中性
dormant 起点；首个状态落 healthy 不告警（healthy 告警=恢复，从无到有谈不上恢复），
落 silent/broken 照旧告警（那是回测开口说话）。见 `docs/adr/026-*.md` 与 dogfood §22。

## 5. 告警分布：0 条——它能核验什么、不能核验什么

4 个月真实历史上 silent / broken / bypassed / degraded 一次都没触发，告警为 0。

- **能下的结论**：无误报。资产层在这份历史上没有制造噪音——监护仪"平时不打扰"成立。
- **不能下的结论**：判定"响的时候一定有事"。四个告警态的**真实**触发从未发生，
  它们的准确率仍只有 fixture 回放背书（P4/P6 的合成测试）。这半边要等真实历史里
  出现第一次静默/损坏才能收口——**P7 的这一项保持未勾**。
